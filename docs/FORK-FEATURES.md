# Fork Features — detail reference

Full detail for the fork-specific features added on top of upstream `bigcapitalhq/bigcapital`. The one-line index lives in `.claude/CLAUDE.md` under **Features added**; this file is the long-form companion. Post-mortems for the bugs these features caused/fixed are in `FORK-BUG-HISTORY.md`.

When adding a feature: add a one-line pointer to `.claude/CLAUDE.md`'s index and the full entry here.

---

- **Bulk activate/inactivate accounts** — `POST /accounts/bulk-{activate,inactivate}` + UI.
- **Edit categorization on bank transactions** — `PATCH /banking/categorize/:id` rewrites GL when account/type changes. "Edit Category" context menu.
- **Parent account name + code in CSV export** — `parentAccountName`/`parentAccountCode` on `AccountTransformer`.
- **Accounts import: parent-child resolution** — two-pass via `afterImport()` on `Importable`; `relationImportMatchDeferred` field-meta flag skips parse-time DB lookup; resolves by id/name/code post-insert.
- **Stripped seed accounts** — `SeedAccounts` has only required predefined accounts. Drawings code 30003 → 30004 (was dup of Owner's Equity).
- **Split-payment expenses + percent-based category allocation** — multi-account payment per expense; categories allocate by percent OR fixed dollar. Tables: `expense_payment_splits`, `expense_transaction_categories.amount_type`/`percent`. Validator tolerance `0.005 + 0.005 × N_percent_rows`. Header `paymentAccountId` denormalized primary for list views. PDF/CSV show only primary (intentional v1). Run tenant migrations.
- **Split-payment-aware bank txn matching** — each split is an independent match candidate via `matched_bank_transactions.reference_sub_id` → `expense_payment_splits.id`. `GetMatchedTransactionsByExpenses` filters by bank txn's account. Unmatch per-split. Form preserves split `id` for `upsertGraph` in-place update.
- **Square integration** — OAuth, setup wizard, HMAC webhooks, SaleReceipt/CreditNote/ManualJournal posting. Phase 1 done; Phase 2 partial (payment done; refund/payout/customer pending); Phase 3 (180-day backfill + Plaid auto-match) planned. See `docs/SQUARE-INTEGRATION.md`.
- **Bidirectional cashflow categorization for refunds** — `OtherIncome` ↔ `OtherExpense` both directions (deposit-as-OtherExpense = vendor refund; withdrawal-as-OtherIncome = customer refund). Sub-form labels direction-aware via `autofillCategorizeValues.isDepositTransaction`. GL writer recovers direction from `cashflow_transactions.uncategorized_transaction_id` source-row sign — `BankTransactionGL` reads `source.amount > 0` for OtherIncome/OtherExpense, overriding fixed `typeMeta.direction`. Commit `3562a0abb` (orig `68a420fc4` read typeMeta verbatim → wrong-direction journal). Old rows need back-link backfill + per-row Edit Category re-save (recipe in commit msg).
- **Credit card as Bill payment account** — `New Payment Made` AccountsSelect + `BillPaymentValidators.getPaymentAccountOrThrowError` allow `CREDIT_CARD` alongside `BANK`/`CASH`/`OTHER_CURRENT_ASSET`. GL account-agnostic (always credits `paymentAccountId`) → CC payment posts `DR AP / CR Credit Card Liability`. Commit `5525a688a`.
- **Vendor-credit refunded-amount sync** — `RefundSyncVendorCreditBalanceSubscriber` was commented out in NestJS migration → `refundedAmount` never bumped, status stuck Open. Re-enabled via `RefundSyncCreditRefundedAmount` (per-id `.findById(id).increment(...)`; sibling table-wide service in same dir has no `where('id',…)` — footgun, leave uncalled). Commit `d40e5b275`. Backfill: `UPDATE VENDOR_CREDITS vc LEFT JOIN (SELECT VENDOR_CREDIT_ID, COALESCE(SUM(AMOUNT),0) AS refunded FROM REFUND_VENDOR_CREDIT_TRANSACTIONS GROUP BY 1) r ON r.VENDOR_CREDIT_ID = vc.ID SET vc.REFUNDED_AMOUNT = COALESCE(r.refunded, 0);`.
- **Reconcile aside accepts equity accounts** — Owner Drawings / Owner Contribution on leftover-amount cashflow txn. Dropdown allows `equity` both directions; `transformToReq` maps via `account_root_type` → `owner_drawing` (withdrawal) / `owner_contribution` (deposit).
- **Direct-account allocations (Bill / VendorCredit / SaleInvoice / CreditNote)** — per-line allocation to an account instead of an item. Tables: `bill_expense_categories`, `vendor_credit_expense_categories`, `sale_invoice_income_categories`, `credit_note_income_categories`. Each model gets `categories` HasMany + `categoriesTotal` virtual; transformer writes `itemsTotal + categoriesTotal` into balance/amount. Submit allows empty `entries` if categories non-empty (vice versa); Delete service cascades. Run tenant migrations. v1: no percent/landed-cost/CSV/PDF. GL direction per type:
  - Bill: DR per category vs expense account; AP CR sums items + categories.
  - VendorCredit: CR per category (mirror of Bill). **`total` getter MUST be `subtotal - discountAmount + adjustment`** — `subtotal === amount` already includes `categoriesTotal` via DTO transformer; adding again doubles AP debit. Commit `771403d4d`.
  - SaleInvoice: CR per category vs income account at indexGroup 15 (items 10, tax 30); AR DR sums both. Commit `877284f72`.
  - CreditNote: DR per category vs income account (reversed vs invoice).
  - **Hydrate-empty-deletes-rows trap (data destruction):** the Get service MUST `.withGraphFetched('categories.<account>')` AND the transformer MUST expose `categories`. Without both, edit form hydrates empty and next save's `upsertGraphAndFetch` deletes every row. Applies to all four.

- **Block GL postings to parent accounts** — parent accounts (any account another account points at via `parent_account_id`) are grouping/subtotal headers in the Chart of Accounts; their report balance is the roll-up of their children. Posting directly to a parent mixes a direct amount into that subtotal and breaks the hierarchy as a clean sum. Enforced server-side at the **single GL chokepoint** `LedgerEntriesStorageService.saveEntries()` (`packages/server/src/modules/Ledger/LedgerEntriesStorage.service.ts`) via `assertNoParentAccountPostings()` — one `whereIn('parentAccountId', accountsIds)` query on the distinct posted-to account ids; any hit throws `ServiceError(ERRORS.POSTING_TO_PARENT_ACCOUNT_NOT_ALLOWED)` naming the offending accounts, which `ServiceErrorFilter` returns as a 400 `{ errors: [...] }` (read by form `onError`). Because **every** GL write funnels through `saveEntries`, this one guard covers all posting paths (invoices, bills, expenses, manual journals, bank categorization, Square, etc.) with no per-service patching. Note: the guard fires the moment an account _acquires_ a child — adding a child to an account that already receives postings (e.g. a bank feed) will start rejecting new postings to that now-parent account (intended: post to a child instead). Does NOT touch the parent-balance cascade in `LedegrAccountsStorage.saveAccountsBalance` (that's a derived balance update, not an `ACCOUNTS_TRANSACTIONS` row) nor `deleteEntries` (cleanup still works).
  - **Webapp: parents hidden from account pickers** — the UX companion to the server guard so parents aren't selectable in the first place. Single chokepoint `usePreprocessingAccounts` (`packages/webapp/src/components/Accounts/_hooks.ts`), which all three pickers (`AccountsSelect`, `AccountsSuggestField` — incl. the `AccountsListFieldCell` line-item cell — and `AccountsMultiSelect`) funnel through. New `hideParentAccounts` option **defaults to `true`**, so all ~37 posting pickers get it with no per-call-site edits. A parent is any account whose id is referenced as another account's `parent_account_id` (read both snake/camel for safety; the parent set is derived from the full unfiltered list, since `nestedArrayToflatten` strips `children`). Two call sites explicitly opt out with `hideParentAccounts={false}` because selecting a parent is legitimate there: the **Account dialog's "Parent Account"** field (`AccountDialogFormContent.tsx` — nesting) and the **General Ledger report** account filter (`GeneralLedgerHeaderGeneralPane.tsx` — not a posting). Edge: a _legacy_ transaction already posted to a now-parent account will render an empty picker row on edit (the usual FSelect "value not in list" symptom) — intended, those postings are what the guard discourages.
  - **Cashflow-accounts page (and its sibling consumers) exclude parents server-side** — the bank/cash account cards aren't an `AccountsSelect`, so the picker filter above doesn't reach them. Filtered at the source instead: `GetBankAccountsService.getCashflowAccounts` (`packages/server/src/modules/BankingAccounts/queries/GetBankAccounts.ts`, route `GET /banking/accounts`) fetches the set of parent ids (`whereNotNull('parent_account_id').distinct(...)` → plain numeric array, deliberately avoiding the snake-case identifier-mapper traps) and adds `builder.whereNotIn('id', parentAccountIds)`. Because this one endpoint also feeds the **MoneyIn/MoneyOut** deposit/withdraw account dropdowns and the **AccountTransactions** sidebar, all four surfaces drop parents at once (correct everywhere — none can post to a parent).
